05 / Procurement intelligence · Multi-portal ingestion

TenderIQ

Lead full-stack architect

Government bids in India sit across GeM and 32 state and central eProcurement portals, and every one of them puts a distorted captcha in front of its own search results. TenderIQ pulls those sources into a single workspace, reads the 80-page tender PDFs, and returns the clauses that decide whether a company should bid at all.

The model does the reading. The queue, the credit ledger, and the per-portal rate limits stay deterministic.

  • 33portals, one search

    How this page is built

    The meta of it, because the constraints are the interesting part.

    Runtime
    Zero-framework vanilla ES modules split on interaction and scroll boundaries, static HTML with inlined font metrics, plus a lazy tree-shaken Three.js rig with Meshopt GLB assets and synthesized Web Audio clicks.
    Weight
    10.6 KB gzipped boot JS, 26.8 KB full CSS, 158.1 KB deferred WebGL/Three.js mascot chunk, plus 283.1 KB Meshopt GLBs and responsive AVIF/WebP imagery loaded on demand.
    Type
    Fraunces for display, IBM Plex Sans for body, and IBM Plex Mono for labels, live telemetry, and statusline readouts.
    Motion
    Compositor-first transforms drive the stacked work deck, horizontal experience theater, hero mesh, Verlet toolkit strings, 3D mascot, and this pull-up drawer. prefers-reduced-motion and the manual toggle settle every scene.
    Data
    Repo telemetry via one unauthenticated GitHub API call cached in sessionStorage for an hour, direct contact delivery via FormSubmit with a mailto: fallback, and a live DOM-reading console.
    Hosting
    GitHub Pages at magraa.github.io, deployed on push with strict CSP rules and self-hosted Three.js — zero third-party JS dependencies.
